## EPLD: what it renders and how each form uses it

The session location is preselected only if it carries the form's tag; `Pharmacy` and `Records Room` (login locations) have no `Consult Note Location`, so their select is empty and "Required" fires. Any other role (nurse, pharmacist, triageStaff, communityHealthWorker, ...) gets a disabled date and provider select.

## Site-wide findings
`formUuid` uniqueness (case-insensitive, boundary `(?<![a-z])formUuid=` so `htmlformUuid` is not counted), per the skill:
- Repo `htmlforms/` (39 files: current, `ncd-*_v1.0.xml`, `retired/`): **no duplicate**. `htmlformUuid` (4 forms) also has no duplicate in the merged tree.
- Merged `~/openmrs/liberia/configuration/pih/htmlforms` (119 files, 38 of them the Liberia repo's top-level forms, byte-identical): **2 duplicates**, both between a Liberia file and a pihemr versioned copy: `3616e6be-1671-4031-9cc9-a0f1f4b1d100` (`med-order.xml`, `section-obgyn-plan_v1.0.xml`) = V2, and `4d778ef4-0620-11e5-a6c0-1697f925ec7b` (`labResults.xml`, `labResults_v1.0.xml`) = V3. Mechanism: `HtmlFormUtil.getHtmlFormFromResourceXml` (htmlformentryui) finds-or-creates the Form by uuid and rewrites name, version and `HtmlForm.xmlData` from whichever file is being opened. Both are Liberia-repo copies that kept the pihemr uuid: the fix belongs in this repo (new `formUuid` + new `formVersion`, or drop the override). Not applied.
- `checkin.xml` has an upper-case uuid (`54E29E26-…`): no collision.
